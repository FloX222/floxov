# FLOXOV: установка и проверка системы репутации

Инструкция рассчитана на уже опубликованный сайт FLOXOV и уже существующий проект Supabase. **Новый сайт и новый проект Supabase создавать не нужно.**

## Что получится

- Like записывает `+1`, Dislike записывает `-1`.
- Первый голос можно оставить сразу после автоматической анонимной авторизации.
- У одного Supabase-пользователя хранится один активный голос.
- Повторное нажатие на уже выбранный вариант не меняет голос и не перезапускает таймер.
- На противоположный голос можно переключиться через 24 часа после первого голоса или последнего успешного изменения.
- Сервер считает общие лайки, дизлайки и репутацию: `likes - dislikes`.
- После обновления страницы голос и таймер восстанавливаются из Supabase.
- На сайте не показываются идентификаторы других голосующих.

## Перед началом: какие файлы менять

В архиве-патче находятся только файлы, которые нужно добавить или заменить. Распаковывай его **в корень существующего репозитория**, сохраняя структуру папок.

| Файл в архиве | Что сделать |
|---|---|
| `assets/supabase.js` | Добавить новый файл |
| `assets/reputation.js` | Заменить существующий файл |
| `FLOXOV_REPUTATION_MIGRATION.sql` | Выполнить в SQL Editor один раз; повторный запуск безопасен |
| `FLOXOV_REPUTATION_VERIFY.sql` | Только проверить результат, не меняет базу |
| `supabase/migrations/202611080002_floxov_reputation_upgrade.sql` | Копия миграции для хранения в репозитории |
| `README_SETUP_RU.md` и `README.md` | Документация |

`index.html`, `assets/main.js`, `assets/styles.css`, изображения, видео и остальные файлы сайта менять не требуется. Текущий HTML уже подключает `assets/reputation.js` как ES-модуль.

**Важно про `assets/config.js`:** в просмотренной копии архива поля `reputation.supabaseUrl` и `reputation.supabaseAnonKey` пустые. Если в актуальном GitHub-репозитории они уже заполнены, оставь свой текущий `assets/config.js` без замены. Если они пустые, заполни их по шагу 4 ниже.

## 1. Открой существующий проект Supabase

1. Открой [Supabase Dashboard](https://supabase.com/dashboard).
2. Войди в тот аккаунт, где уже находится проект FLOXOV.
3. На странице проектов выбери **существующий проект**, который уже использует сайт.
4. Проверь название проекта в верхней панели, чтобы не открыть другой проект.

Ничего нового создавать не нужно.

## 2. Проверь анонимную авторизацию

1. В левом меню проекта открой **Authentication**.
2. Перейди в **Sign In / Providers** (в некоторых вариантах интерфейса раздел может называться **Providers**).
3. Найди провайдер **Anonymous Sign-Ins** / **Anonymous**.
4. Убедись, что переключатель включён.
5. Если он уже включён, ничего не меняй.

Ожидаемый результат: анонимная регистрация разрешена. Посетителю сайта не нужно заполнять форму, вводить почту или пароль.

## 3. Найди URL и публичный ключ проекта

1. В верхней панели существующего проекта нажми **Connect**. В этом окне отображаются **Project URL** и публичный ключ для подключения.
2. Для просмотра и выбора ключа открой **Project Settings → API Keys**.
3. Скопируй **Project URL** из окна Connect (или из раздела Data API, если он отображается в меню проекта).
4. Скопируй публичный ключ **Publishable key**. В старых проектах он может отображаться как `anon` / `anon public`.

Для браузерного сайта нужен именно публичный Publishable key (или уже используемый legacy `anon` key). В `assets/config.js` не нужно помещать `service_role` или secret key. Официальные инструкции: [Anonymous Sign-Ins](https://supabase.com/docs/guides/auth/auth-anonymous) и [API Keys](https://supabase.com/docs/guides/getting-started/api-keys).

## 4. Проверь подключение в `assets/config.js`

Открой `assets/config.js` в репозитории GitHub. Найди блок:

```js
reputation: {
  supabaseUrl: "",
  supabaseAnonKey: ""
},
```

Если значения уже заполнены и относятся к существующему проекту, оставь их как есть. Если поля пустые, вставь свои значения:

```js
reputation: {
  supabaseUrl: "https://ТВОЙ-PROJECT-REF.supabase.co",
  supabaseAnonKey: "ТВОЙ-ПУБЛИЧНЫЙ-PUBLISHABLE-ИЛИ-ANON-КЛЮЧ"
},
```

Не меняй остальные настройки в `config.js`. Сохрани запятую после закрывающей фигурной скобки, если после блока `reputation` идут другие настройки.

## 5. Примени SQL-миграцию

Этот файл **изменяет базу данных**: создаёт или дополняет таблицу, включает RLS, настраивает права и создаёт две RPC-функции. Существующие голоса не удаляются.

1. В левом меню Supabase открой **SQL Editor**.
2. Нажми **New query**.
3. Открой локальный файл `FLOXOV_REPUTATION_MIGRATION.sql` из архива.
4. Скопируй его содержимое целиком.
5. Вставь в SQL Editor.
6. Нажми **Run**.
7. Дождись сообщения об успешном выполнении.

Если SQL остановился с ошибкой о несовместимой схеме или старых данных, не удаляй таблицу и не очищай строки. Скопируй полный текст ошибки: миграция намеренно останавливается, если обнаруживает неизвестную структуру, вместо того чтобы стирать данные.

### Что миграция настраивает

- `public.floxov_votes`: `voter_id`, `vote`, `created_at`, `changed_at`.
- `voter_id` — первичный ключ и внешний ключ на `auth.users(id)`.
- `vote` допускает только `-1` и `+1`.
- `changed_at` допускает `NULL`: это отметка последующего изменения голоса.
- RLS включён; прямое чтение ограничено собственной строкой, прямые INSERT/UPDATE/DELETE запрещены.
- `vote_floxov(p_vote)` записывает голос и проверяет 24-часовой интервал на стороне PostgreSQL.
- `get_floxov_reputation()` возвращает общую статистику и голос текущего пользователя.

## 6. Проверь базу данных отдельным SQL-файлом

`FLOXOV_REPUTATION_VERIFY.sql` **ничего не изменяет**. Он только проверяет таблицу, типы колонок, ограничения, RLS, политики, права и функции.

1. Вернись в **SQL Editor**.
2. Нажми **New query**.
3. Открой `FLOXOV_REPUTATION_VERIFY.sql`.
4. Скопируй весь файл и вставь в редактор.
5. Нажми **Run**.

Ожидаемый результат: в первой таблице напротив всех критических проверок стоит `PASS`. Если есть `FAIL`, система ещё не прошла проверку. Не переходи к публикации, пока не выяснена причина.

В конце результата будет сводка `likes`, `dislikes`, `reputation` и `total_votes`. Идентификаторы пользователей этот запрос не выводит.

## 7. Добавь JavaScript-файлы в существующий сайт

В корне GitHub-репозитория должны находиться папки `assets` и `supabase`.

1. Скопируй `assets/supabase.js` в папку `assets` сайта.
2. Замени существующий `assets/reputation.js` новой версией из архива.
3. Сохрани свой `assets/config.js` с уже настроенными значениями Supabase.
4. Не удаляй и не заменяй `index.html`, `main.js`, `styles.css`, медиафайлы и другие файлы.

Новый `reputation.js` импортирует `supabase.js` автоматически. Отдельно добавлять второй `<script>` в HTML не нужно.

## 8. Загрузи изменения на GitHub Pages

1. Открой GitHub и зайди в репозиторий опубликованного FLOXOV.
2. Убедись, что выбрана ветка, из которой публикуется сайт (обычно `main`).
3. Загрузи два файла в существующую папку `assets` с заменой `reputation.js` и добавлением `supabase.js`.
4. Загрузи SQL-файлы и README в корень репозитория; миграцию также положи в `supabase/migrations/`.
5. Создай commit, например `Implement FLOXOV reputation system`.
6. Открой **Settings → Pages** и проверь, что выбран прежний источник публикации. Если сайт уже опубликован, менять источник не нужно.
7. Дождись завершения GitHub Pages deployment в разделе **Actions** или в настройках Pages.

## 9. Проверь работу сайта

Открой опубликованный сайт по HTTPS. Если браузер держит старые файлы, сделай жёсткое обновление страницы или открой сайт в приватном окне.

### Проверка в двух браузерных сессиях

- **Сессия A:** обычное окно браузера. Открой сайт, дождись загрузки статистики и нажми Like.
- **Сессия A:** обнови страницу. Должны сохраниться выбранный Like и оставшееся время до изменения.
- **Сессия A:** нажми Like ещё раз. Счётчики не должны измениться, а таймер не должен начаться заново.
- **Сессия A:** нажми Dislike до истечения 24 часов. Сервер должен вернуть `cooldown`; голос останется Like.
- **Сессия B:** открой сайт в другом браузере или отдельном профиле. Общие числа Like/Dislike и репутация должны совпасть с сессией A. Выбор голоса в сессии B изначально не отмечен.
- **Сессия B:** нажми Dislike. Глобальные числа должны измениться на один голос, а в сессии A новые значения появятся после фонового обновления (до 60 секунд), обновления страницы или следующего успешного голосования.
- **После 24 часов:** в сессии A попробуй изменить Like на Dislike. Старый голос должен замениться, а не прибавиться к общему количеству.

### Чек-лист критических сценариев

| Проверка | Ожидаемый результат |
|---|---|
| Первая анонимная авторизация | Сессия создаётся без формы регистрации |
| Первый Like | `likes +1`, `reputation +1` |
| Первый Dislike в отдельной сессии | `dislikes +1`, `reputation -1` |
| Повтор того же голоса | Статистика не меняется, таймер не сбрасывается |
| Противоположный голос до 24 часов | Статус `cooldown`, старый голос остаётся |
| Противоположный голос после 24 часов | Старый голос заменяется новым |
| Перезагрузка страницы | Голос и таймер восстановлены |
| Две сессии | Глобальные числа совпадают |
| Права RPC | `authenticated` может вызывать обе функции; `anon` и `PUBLIC` не могут |
| RLS | Прямое чтение возможно только собственной строки; прямые записи запрещены |
| Мобильный браузер | Кнопки доступны, статистика не выходит за границы виджета |

## 10. Если что-то не работает

**Показывается сообщение о ненастроенном Supabase**

- Проверь, что в `assets/config.js` заполнены оба поля: `supabaseUrl` и `supabaseAnonKey`.
- Проверь, что изменения действительно загружены в GitHub Pages.

**Ошибка авторизации / Anonymous sign-in disabled**

- Открой Authentication → Sign In / Providers.
- Проверь, что Anonymous Sign-Ins включён.

**`function not found` / `PGRST202`**

- Выполни `FLOXOV_REPUTATION_MIGRATION.sql` в нужном Supabase-проекте.
- Подожди несколько секунд и обнови страницу.

**`permission denied` / `42501`**

- Запусти `FLOXOV_REPUTATION_VERIFY.sql`.
- Проверь, что функции доступны роли `authenticated`, а не только `postgres`.

**Голос не сохраняется после обновления**

- Убедись, что браузер не блокирует сайтам локальное хранилище.
- Открой сайт в обычном окне и проверь, что сессия не удаляется настройками браузера.

**Счётчики не обновились во второй вкладке**

- Фоновое обновление происходит примерно раз в 60 секунд; можно обновить страницу вручную.

## Что означает «готово»

Код и SQL подготовлены, но считать систему проверенной на твоём реальном проекте можно только после выполнения миграции и прохождения критического чек-листа выше. Пока SQL не запускался в твоём Supabase и тесты не выполнены в двух браузерных сессиях, это не подтверждённый production deployment.
